# Структура сайта проекта «MathVizor»

Материал подготовлен на основе документа «Лучшая онлайн-разработка» (статья-заявка на номинацию). Сайт планируется как **статический HTML-сайт** без серверной части и CMS.

> Рабочая HTML-версия этого документа с каркасом кода и кнопками копирования: **`Структура_сайта.html`** (открывается в браузере).
>
> **Готовый сайт:** 10 страниц в этой папке, стили — `assets/css/style.css`, скрипт — `assets/js/main.js`, изображения — `assets/img/`. Демо-версия исключена. Подробная инструкция — `README.md`. Пересборка страниц из каркаса: `python build_site.py`. Проверка ссылок: `python check_links.py`.

Евсевьева (`https://www.mordgpi.ru/`), сохранённые в `assets/img/screenshots/`. Источник указан в подписях к изображениям. Скриншот из материалов заявки (`01-workspace.jpg`) оставлен на странице «Платформа».

## 1. Назначение и аудитория

**Цель сайта:** представить платформу MathVizor жюри номинации, методистам и преподавателям как готовую онлайн-разработку, которую можно открыть, понять и применить.

**Аудитории:**

| Аудитория | Что ищет на сайте | Ведущая страница |

| Жюри номинации | Суть разработки, новизну, результаты, публикации | `index.html`, `results.html`, `publications.html` |
| Учителя / преподаватели | Педагогический дизайн, методику, пример урока, задания | `pedagogy.html`, `methodology.html`, `tasks.html` |
| Разработчики / методисты | Архитектуру, стек, интеграции, доступность | `technology.html` |
| Студенты / школьники | Как работать с платформой, примеры заданий | `tasks.html`, `methodology.html` |
| Партнёры / вуз | Авторов, публикации, контакты | `about.html`, `publications.html` |

## 4. Детальная структура страниц

### `index.html` — Главная

1. **Hero-блок.** Название «MathVizor», подзаголовок «Интерактивная платформа для развития математического моделирования и исследовательских компетенций», плашка номинации, две кнопки: «Познакомиться с платформой» и «Читать статью».
2. **Ключевые цифры (4 карточки):** `4` модуля платформы · `86` обучающихся в апробации · `+24 п.п.` прирост верных заданий в эксперименте · `9–11 классы и 1–2 курсы`.
3. **«Зачем нужен MathVizor».** Проблема из введения: разрыв между необходимостью исследовательских компетенций и возможностями учебника/КАС/тестов (пошаговая обратная связь, индивидуализация).
4. **«Как это работает».** Короткая схема из 4 шагов: визуализация → гипотеза → символьная проверка → рефлексия (связка с разделом 3).
5. **«Что внутри».** 4 карточки модулей (Визуализация, Вычисления, Практика, Аналитика) с иконками и ссылками на `platform.html`.
6. **«Результаты»** — мини-диаграмма до/после (54→78 % против 53→64 %) + ссылка «Подробнее об исследовании» → `results.html`.
7. **«Кто реализовал»** — ФГБОУ ВО «Мордовский государственный педагогический университет им. М. Е. Евсевьева», автор, научный руководитель → `about.html`.
8. **Финальный CTA** — «Узнать результаты апробации» → `results.html`.

### `platform.html` — Платформа

1. Хлебные крошки: Главная / Платформа.
2. **Обзор** — платформа как веб-приложение в браузере, без установки ПО; непрерывный цикл «постановка задачи — модель — эксперимент — объяснение — рефлексия».
3. **Интерфейс.** Описание рабочего листа: слева условие и инструменты, в центре график/конфигурация, справа панель пошагового решения. Обязательно вставить скриншот с подписью «Рисунок 1 — рабочий лист MathVizor» (в исходном docx изображение было в пакете, но не выведено в текст).
4. **4 модуля** — карточки с расшифровкой из раздела 2.
5. **Таблица 1** «Соответствие компонентов платформы педагогическим задачам» — семантическая `<table>` с `<caption>`, 4 строки, 3 столбца (Компонент / Педагогическая задача / Ожидаемый эффект).
6. **Сдержанный стиль интерфейса** — пояснение, что игровые элементы не отвлекают от математики; мотивация через сюжет и сравнение гипотезы с результатом.
7. Ссылки вниз: `technology.html`, `tasks.html`.

### `technology.html` — Архитектура и технологии

1. **Схема трёхслойной архитектуры** (Client → API → Data), желательно inline SVG.
2. **Клиент:** TypeScript, React, SVG, Canvas — плюсы: браузер, без доп. ПО, динамическая визуализация.
3. **Сервер:** Python, FastAPI, SymPy (символьные вычисления), сервисы генерации заданий и аналитики.
4. **Данные и фоновые задачи:** PostgreSQL, Redis, Celery.
5. **Интеграции:** LTI 1.3 и xAPI для LMS — блок «Подключение к электронной образовательной среде вуза».
6. **Доступность:** WCAG 2.1 — текстовые дубли графиков, управление с клавиатуры; указать проверенный уровень (A/AA) после аудита.
7. **Развёртывание:** Docker, модульность, расширение новыми разделами математики.
8. **Важно для сайта:** адрес платформы (если он появится) указывать в разделе публикаций/контактов; формулировки «адрес демонстрационный, подлежит замене» в публичную версию не переносить.

### `tasks.html` — Задания и обратная связь

1. **4 типа заданий** — карточки или вкладки:
   - распознавание структуры (график ↔ формула ↔ описание);
   - построение модели (изменение параметров);
   - объяснение (выбор корректного обоснования перехода);
   - исследовательские (гипотеза → проверка → аргументация).
2. **3 уровня обратной связи** — схема/таблица: сигнальный → объясняющий → рефлексивный, с пояснением «система не даёт готовый ответ».
3. **Журнал подсказок** — как обращения фиксируются и помогают преподавателю строить индивидуальную траекторию.
4. **Пример задания** — интерактивный блок с ползунком параметра (можно на чистом JS + SVG) или статичный скриншот.
5. CTA → `methodology.html`.

### `pedagogy.html` — Педагогический дизайн

1. **Концепция «видимого мышления»** — каждый этап решения представлен в наглядной и обсуждаемой форме.
2. **Принципы:** наглядность, доступность, индивидуализация, обратная связь — 4 карточки.
3. **Таксономия учебных целей:** «знать → понимать → применять → анализировать → создавать» — визуальная лестница с сопоставлением типов заданий.
4. **От электронного учебника к пространству эксперимента** — сравнительный блок (таблица «Было / Стало»).
5. **Анализ аналогов** (из раздела 1): GeoGebra/Cabri, Desmos, Wolfram Mathematica/SymPy, Stepik/Coursera/Khan Academy, тренажёры — таблица с колонками «Что даёт / Ограничение». Рекомендуется дополнить конкретными адаптивными системами и довести до корректного сравнения.
6. CTA → `methodology.html`, `results.html`.

### `methodology.html` — Методика использования

1. **4 этапа исследовательского цикла** — нумерованный таймлайн:
   1. Проблемная ситуация и фиксация гипотез (пример: «Как изменение коэффициента при x влияет на число экстремумов?»).
   2. Построение семейства графиков, варьирование параметров, поиск критических значений.
   3. Связь наглядного и аналитического уровней (символьное подтверждение).
   4. Рефлексия: сопоставление гипотезы и вывода.
2. **Пример фрагмента урока** «Производная и исследование функции»: f(x) = x³ − 3x; предсказание числа экстремумов → график → f′(x)=3x²−3 → точки x=±1 → объяснение смены знака → рефлексия (что дала визуализация, что — аналитика). Оформить как пошаговый аккордеон.
3. **Работа с ошибкой** — система показывает шаг расхождения, не прерывая работу.
4. **Режим агрегированной аналитики для преподавателя** — доля неверных гипотез, распределение времени, типичные ошибки.
5. **Очные и дистанционные варианты** — сохранение логики цикла.
6. CTA → `tasks.html`, `methodology.html`.

### `results.html` — Результаты апробации

1. **Дизайн исследования:** семестр, 44 человека в экспериментальной и 42 в контрольной группе, 86 всего; диагностика — смысл производной, интерпретация графиков, прикладные задачи на моделирование.
2. **Динамика верных заданий:** 54 % → 78 % (эксперимент), 53 % → 64 % (контроль); акцент: прирост +24 п.п. против +11 п.п.
3. **Таблица 2** «Динамика показателей диагностики» — 4 строки; обязательно:
   - уточнить, что 41 % / 72 % — межгрупповое сравнение «Обоснованные гипотезы», а не динамика (иначе вывод текста не подтверждается данными);
   - указать шкалу индекса удовлетворённости (например, 1–5) и наименование столбцов.
4. **Опрос:** 87 % отметили помощь визуализации, 79 % — пользу пошаговой обратной связи; преподаватели — сокращение времени на рутинную проверку.
5. **Статистика:** t-критерий Стьюдента и U-критерий Манна — Уитни, p < 0,05, совпадение выводов; при публикации дополнить M±SD и размером эффекта.
6. **Ограничения честно:** выборка не репрезентативна, длительность — один семестр; вычислительные навыки изменились в обеих группах одинаково.
7. CTA → `publications.html`.

## 7. Технические заметки для реализации на чистом HTML

1. Каждая страница — самодостаточный документ: `<!doctype html>`, `<html lang="ru">`, `<meta charset="utf-8">`, `<meta name="viewport">`, уникальные `<title>` и `<meta name="description">`, Open Graph-теги.
2. Поскольку серверной части нет, **шапку и подвал придётся продублировать** в каждом HTML-файле (альтернатива — JS-подключение через `fetch`, но при открытии с `file://` оно блокируется; для локального просмотра надёжнее дублирование).
3. Активный пункт меню отмечать классом `is-active` вручную в каждом файле; скролл-спай — опционально.
4. Таблицы 1 и 2 сверстать семантически: `<caption>`, `<thead>`, `<th scope="col|row">`, `<tbody>`.
5. Диаграммы результатов делать на inline SVG или CSS-полосами — без внешних библиотек (сайт останется лёгким и автономным).
6. Изображения — в `webp` с fallback в `png/jpeg`; обязательные `alt` и подписи.
7. Перед публикацией: загрузить всю папку на хостинг, обновить метаданные файлов, проверить все ссылки (внутренние и внешние) и валидность разметки. Сборка не требуется.
